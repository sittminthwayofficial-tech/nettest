# VPN Harvester — Feed အရင် (Phase 1, Step 1)

ဒါက **app မဟုတ်ပါ** — အခမဲ့ proxy config တွေကို ၃ နာရီ တစ်ခါ အလိုအလျောက်
လိုက်စုပြီး၊ တကယ် အလုပ် လုပ် မလုပ် စမ်းပြီး၊ အလုပ်လုပ်တာတွေကိုပဲ
**subscription feed** အဖြစ် ထုတ်ပေးတဲ့ စနစ် တစ်ခုပါ။ မင်း ဖုန်းက အဲဒီ feed ကို
ဆက်တိုက် ဆွဲနေရင် အမြဲ လတ်ဆတ်တဲ့ node တွေ လက်ထဲ ရှိနေမယ်။

ဘာကြောင့် ဒီပုံစံ လဲ: Phase 0 မှာ တိုင်းပြီးသား အဖြေတွေ —
- node တွေက တစ်ရက် အတွင်း ~31% ပဲ အသက်ရှင်တယ် → စာရင်း အသေ မရဘူး၊ refresh ပဲ အသက်
- curated source (NoMoreWalls) က mega-pool ထက် အလုပ်လုပ်နှုန်း ~5 ဆ ကောင်းတယ်
  → စမ်းခကို အရင် source ကောင်း တွေမှာ အရင် သုံးတယ် (sources.txt အစဉ် = ဦးစားပေး အစဉ်)

## မင်း လုပ်ရမှာ (၅ မိနစ် ခန့်၊ တစ်ခါပဲ)

### ၁. GitHub repo အသစ် ဆောက် (Public ရွေးပါ)
1. github.com ဝင်၊ မင်း account နဲ့ login ဝင် (account မရှိရင် အရင် ဖွင့်)
2. ညာဘက် အပေါ်က **+** → **New repository**
3. Repository name: ကြိုက်တာ ပေး (ဥပမာ `vpn-feed`)
4. **Public** ကို ရွေး — ⚠️ ဒါ အရေးကြီးတယ်: Public repo ဆိုရင် GitHub Actions
   မိနစ် အကန့်အသတ် မရှိ အခမဲ့ ရတယ်။ Private ဆို တစ်လ မိနစ် 2,000 ပဲ ရပြီး ကုန်တတ်တယ်။
   (config တွေက မူလကတည်းက အများသူငါ data တွေပဲ၊ ဖုံးစရာ လျှို့ဝှက်ချက် မပါဘူး)
5. **Create repository** နှိပ်

### ၂. ဒီ package file တွေ တင်
1. repo စာမျက်နှာမှာ **Add file** → **Upload files**
2. zip ဖြည်ထားတဲ့ folder ထဲက file/folder **အကုန်** ရွေးပြီး drag ချ / ရွေးတင်:
   `harvester.py`, `phase0_core.py`, `sources.txt`, `README_MY.md`, `feed/` folder,
   ပြီးတော့ **`.github` folder** (ဒါ အရေးကြီးဆုံး — workflow က ဒီထဲမှာ)
3. **Commit changes** နှိပ်

⚠️ `.github` folder က computer မှာ မျက်စိနဲ့ မမြင်ရရင် (hidden ဖြစ်နေတတ်):
repo စာမျက်နှာမှာ **Add file** → **Create new file** ကိုသွား၊ file name နေရာမှာ
`.github/workflows/harvest.yml` လို့ အတိအကျ ရိုက် (slash ပါရင် folder အလိုလို ဖြစ်မယ်)၊
ပြီးရင် zip ထဲက harvest.yml အထဲက စာသား အကုန် copy/paste ထည့်၊ Commit နှိပ်။

### ၃. Actions ဖွင့်ပြီး ပထမ run ကို လက် နဲ့ စ
1. repo အပေါ်က **Actions** tab နှိပ် (ပထမဆုံး ဆိုရင် "I understand..." ခလုတ် ပေါ်ရင် နှိပ်ပြီး ဖွင့်)
2. ဘယ်ဘက်မှာ **Harvest VPN feed** တွေ့မယ် → နှိပ်
3. **Run workflow** → အစိမ်းရောင် **Run workflow** ခလုတ် နှိပ်
4. run တစ်ခု စမယ် — နှိပ်ပြီး ကြည့်နေလို့ ရတယ်။ တစ်ခုလုံး **၁၅–၂၅ မိနစ်** ခန့် ကြာနိုင်တယ်
   (node စမ်းရတာ မူရင်း အလုပ်)။ အဆင့် အားလုံး အစိမ်း ✓ ဖြစ်ရင် အောင်ပြီ။
5. အနီရောင် ✗ ဖြစ်ရင် run ထဲ ဝင်ပြီး ဘယ် step ကျ လဲ ဆရာသမား (Muse) ကို screenshot ပို့လိုက်

အောင်ပြီးရင် နောက်ပိုင်း **၃ နာရီ တစ်ခါ အလိုအလျောက်** run နေမယ်၊ မင်း ဘာမှ လုပ်စရာ မလိုဘူး။
repo ရဲ့ `feed/` folder ထဲမှာ `working.b64` file ကို bot က အလိုအလျောက် update လုပ်ပေးနေမယ်။

### ၄. မင်း feed URL
ပထမ run အစိမ်း ပြီးရင် URL က ဒီပုံစံ:

```
https://raw.githubusercontent.com/<မင်း GitHub နာမည်>/<repo နာမည်>/main/feed/working.b64
```

ဥပမာ: `https://raw.githubusercontent.com/alexkyaw/vpn-feed/main/feed/working.b64`
(repo နာမည်နဲ့ branch နာမည်က မင်း ထားတဲ့ အတိုင်း။ branch က `main` မဟုတ်ရင် အဲဒီ အတိုင်း ပြင်)

### ၅. v2rayNG မှာ Subscription အဖြစ် ထည့် (ဖုန်း)
1. v2rayNG ဖွင့် → ညာဘက် အပေါ် **⋮** မီနူ → **Subscription settings**
2. **+** နှိပ် → remarks မှာ နာမည် ပေး (ဥပမာ `my-feed`)၊ **URL** နေရာမှာ အပေါ်က URL paste
3. သိမ်း → ပြီးရင် မီနူက **Update subscription** နှိပ် — node တွေ ဝင်လာမယ်
4. Subscription setting ထဲမှာ **auto update** ရှိရင် ဖွင့်ပြီး ကြားကာလ **180 မိနစ် (၃ နာရီ)** ထား
   (မရှိလည်း ကိစ္စ မရှိ — သုံးခါနီး Update subscription လက် နဲ့ နှိပ်ရုံပဲ)
5. node တစ်ခုရွေး → အောက်က ▶ နဲ့ connect။ **ချိတ်တဲ့ node တိုင်းကို သုံးခါနီး ဖုန်းကပဲ
   ပြန် စစ် သလို ရွေး** — အောက်က "ရိုးရိုးသတိ" ကို ဖတ်။

## ရိုးရိုး သတိ (ဒါတွေ မဖြစ်မနေ သိထား)

- **စမ်းတဲ့ နေရာက GitHub server (အမေရိကန်/ဥရောပ)၊ မင်း ဖုန်းက မြန်မာ။** feed ထဲ ပါတဲ့
  node က "GitHub server ဆီကနေ အလုပ်လုပ်တာ သေချာတယ်" ပဲ အဓိပ္ပာယ် ရတယ်။
  မြန်မာ ISP က ပိတ်ထားတဲ့ လမ်းကြောင့် node တချို့ မင်းဆီက မရနိုင်ဘူး — အဲဒါ ပုံမှန်ပဲ၊
  bug မဟုတ်ဘူး။ ဒါကြောင့် v2rayNG ထဲမှာ node ပြောင်း စမ်း ရတာ၊ app တွေ ကိုယ်တိုင်
  connect မလုပ်ခင် ပြန်စစ်တာက နောင်တစ်ချိန် app ဆောက်ရင် ထည့်ရမယ့် အချက်ပဲ။
- **မြန်နှုန်း/gaming ကတိ လုံးဝ မပေးဘူး။** တိုင်းထားတာ: အကောင်းဆုံး node လေးတွေတောင်
  ~550 ms က စ တယ်။ Facebook / YouTube / web အတွက်ပဲ။ gaming ဆို လုံးဝ မဖြစ်။
- **privacy/security VPN မဟုတ်ဘူး။** node တွေက သူများ server — မင်း traffic ကို သူတို့ မြင်နိုင်တယ်။
  ဘဏ်/ငွေကြေး လို အရေးကြီးတာတွေ ဒါနဲ့ မလုပ်နဲ့။ "အခမဲ့ ဝင်လမ်း" လို့ပဲ သဘောထား။
- **feed ရဲ့ အရည်အသွေး မှတ်တမ်း:** `feed/history.csv` မှာ run တစ်ခါတိုင်း စာရင်း တစ်ကြောင်း
  တိုးတယ် (ဘယ်နှစ် ခု ရှာတွေ့၊ ဘယ်နှစ် ခု အလုပ်လုပ်)။ **၁ ပတ်** လောက် စုပြီးရင်
  ဆက်တိုက် working အရေအတွက် ပုံမှန် ရှိမရှိ ဆရာသမား နဲ့ အတူ ကြည့်ပြီး
  app ဆောက်မလား/မဆောက်ဘူးလား ဆုံးဖြတ်မယ်။

## ပြင်ချင် ရင်

- **source ထပ်/ဖယ်:** `sources.txt` ကို GitHub ပေါ်မှာပဲ edit လုပ်လို့ ရတယ်
  (အစဉ် = စမ်းမယ့် ဦးစားပေး အစဉ်၊ အပေါ်ဆုံး က အရင်)
- **စမ်းတဲ့ အရေအတွက် တိုး/လျော့:** Actions → Run workflow မှာ core_limit ပြောင်းရိုက်လို့ ရတယ်
  (default 800။ များလေ ကြာလေ၊ 15–25 မိနစ် target ကို မကျော်စေနဲ့)
- **ဖိုင် ရှင်းလင်းချက်:** `harvester.py` = စီမံ/စမ်းသပ်ပင်၊ `phase0_core.py` = Phase 0 က
  စမ်းပြီး သား tester core (မပြင်ရ)၊ `feed/stats.json` = နောက်ဆုံး run အသေးစိတ်၊
  `feed/working.txt` = လူ ဖတ်လို့ ရတဲ့ working စာရင်း၊ `feed/working.b64` = ဖုန်းထဲ သွင်းတဲ့ subscription file
